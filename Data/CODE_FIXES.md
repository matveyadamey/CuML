## 🔴 Критично: утечки и неверные таргеты

### 1. Фундаментал присоединяется по календарному году (утечка из будущего)

**Где:** блок «10. Merge Smart-Lab Fundamentals», ~стр. 283–291.

```python
df["year"] = df["date"].dt.year
df = df.merge(fund_sub, on=["ticker", "year"], how="left")
```

**Проблема.** Строки за январь 2023 получают годовую прибыль за 2023, которая станет известна только в феврале–марте 2024. Значения «за 2026» — по-видимому, LTM-колонка Smart-Lab, распознанная как год. Часть цифр не сходится с отчётностью (ВТБ 2024: 535,3 млрд в датасете против 551,4 млрд по МСФО; ВТБ 2022: −619,5 — проверить).

**Как исправить.**
- В `parse_smartlab_fundamentals.py` для каждого отчёта сохранять дату публикации (`report_date`). Если её нет — консервативно считать, что годовой отчёт за год Y доступен с 1 апреля Y+1.
- Присоединять через `pd.merge_asof(df.sort_values("date"), fund.sort_values("available_from"), left_on="date", right_on="available_from", by="ticker", direction="backward")`.
- Отбросить LTM-колонку или хранить её отдельно с датой.
- Сверить парсер с отчётностью хотя бы для SBER и VTBR.

### 2. `ffill()` по всей таблице переносит значения между тикерами и из будущего

**Где:** блоки 7–9, ~стр. 248–281.

```python
df = pd.merge_asof(df, zcyc..., on="date")     # df теперь отсортирован по date, а не по (ticker, begin)
...
df[f"{prefix}_close"] = df[f"{prefix}_close"].ffill()
df["key_rate_pct"] = df["key_rate_pct"].ffill()
df["liquidity_deficit_surplus_bln_rub"] = df["liquidity_deficit_surplus_bln_rub"].ffill()
```

**Проблема.** После `merge_asof` строки внутри одной даты идут по тикерам, а не по времени. Если у AVAN в 10:00 нет котировки золота, `ffill` возьмёт значение из предыдущей строки — например, SBER в 18:00 того же дня. Проверка: в 16 897 из 49 617 часов (34%) у разных тикеров в одно и то же время разное `gold_close`; для `cny_close` — 9 042, для `rgbi_close` — 9 748.

**Как исправить.**
- Заполнять пропуски в самом макро-ряду **до** merge: построить полную сетку часов (`begin`) из всех тикеров, сделать `reindex` макро-ряда на эту сетку и `ffill` по времени.
- Либо присоединять через `pd.merge_asof(df.sort_values("begin"), adf.sort_values("begin"), on="begin", direction="backward")` — тогда берётся последнее известное значение на момент свечи.
- Для дневных рядов (ставка, ликвидность) — тоже `merge_asof` по дате вместо `merge` + `ffill`.
- После всех merge вернуть сортировку `["ticker", "begin"]`.
- Добавить тест: `df.groupby("begin")["gold_close"].nunique().max() == 1`.

### 3. Календарь таргетов строится по датам IMOEX, в которых есть дыры

**Где:** блок «3. MOEX Trading Calendar & Target Dates», ~стр. 64–98.

```python
imoex_dates = sorted(df[df["ticker"] == "IMOEX"]["date"].unique())
```

**Проблема.** В выгрузке IMOEX пропущены целые периоды: разрывы в 33 дня (до 01.02.2021), 34 дня (до 01.04.2021), 27 дней (до 24.03.2022 — это настоящая остановка торгов), 32 дня (до 01.09.2025), плюс 6–11 дней на январских праздниках. Из-за этого `target_date_1d` у части строк на месяц вперёд, а статус `OK` (пример: AVAN 26.02.2021 → таргет 01.04.2021).

**Как исправить.**
- Брать календарь из объединения дат всех тикеров или из официального календаря торгов MOEX, а не из одного индекса.
- Добавить проверку: `(target_date_1d - date).dt.days <= 5` для всех строк со статусом `OK`, кроме известных остановок; остальные помечать `NO_DATA`.
- Перекачать IMOEX за пропущенные периоды (похоже на сбой пагинации в сборщике).

## 🟠 Важно: некорректные признаки

### 4. TCSG и T не склеены

**Где:** `INSTRUMENT_METADATA` и логика lineage (~стр. 6, 28–39, 60–62). В описании заявлена склейка, в коде только общий `issuer_id = "TCS"`.

**Проблема.** Оба тикера присутствуют одновременно в 3 191 часе (03.01–27.11.2024) с ценами в разном масштабе (~2 385 против ~323 ₽). В val попадают дубли одного эмитента; `peer_*` признаки для других банков считают Т-Банк дважды (если оба торгуются).

**Как исправить.** Выбрать один ряд на каждую дату (например, T с даты начала его основной ликвидности, TCSG до неё), привести цены TCSG к масштабу T коэффициентом на дату перехода, оставить один тикер (`T`) с флагом `instrument_switch`.

### 5. Нули вместо пропусков в доходностях макро-рядов

**Где:** ~стр. 275–281.

```python
adf[f"{prefix}_return_1d"] = adf["close"].pct_change(9)
df[f"{prefix}_return_1d"] = df[f"{prefix}_return_1d"].fillna(0.0)
df[f"{prefix}_return_1h"] = df[f"{prefix}_return_1h"].fillna(0.0)
```

**Проблема.** `gold_return_1d` равен 0 в 46% строк, `cny_return_1d` — в 25%, `rgbi_return_1d` — в 20%. Модель видит «рынок не изменился» там, где данных просто нет. Плюс «1d» = 9 свечей, что не совпадает с днём при вечерней сессии.

**Как исправить.** Считать доходности после выравнивания на сетку (п. 2), дневную — от закрытия предыдущего дня (`close / prev_day_close - 1`), пропуски оставлять `NaN` или добавить флаг `*_is_missing`. То же для `opening_gap.fillna(0.0)` (~стр. 230).

### 6. `return_1d` / `return_1w` считаются по числу свечей

**Где:** `build_moex_banks_dataset.py`, стр. 259–262 (и дубль в `run_parallel_collector.py`, стр. 227–229).

```python
df["return_1d"] = c.pct_change(10)  # ~1 trading day
df["return_1w"] = c.pct_change(50)  # ~1 trading week
```

**Проблема.** С утренней и вечерней сессиями в дне до ~17 часовых свечей, а у неликвидных бумаг — 1–2. «1d» у SBER и у AVAN — совершенно разные интервалы. То же с `return_1h`: в ~11% строк соседние свечи разнесены больше чем на час (у AVAN, USBN, CBOM — на дни), отсюда выбросы до 80% за «час».

**Как исправить.** `return_1d` = close / close последней свечи предыдущего торгового дня − 1; `return_1w` — относительно закрытия дня неделю назад (через `merge_asof` по времени). Для `return_1h` — `NaN`, если предыдущая свеча старше часа (или добавить признак `hours_since_prev_bar`).

### 7. Минуты сессии захардкожены под 10:00–18:40

**Где:** ~стр. 146–148.

```python
df["session_minute_now"] = np.clip((df["hour"] - 10) * 60 + 60, 0, 520)
df["minutes_left_today"] = np.maximum(0, 520 - df["session_minute_now"])
df["minutes_to_target_1d"] = df["minutes_left_today"] + 520
```

**Проблема.** Для свечей 06:00–09:00 `session_minute_now = 0`, для вечерних 19:00–23:00 — 520 и `minutes_left_today = 0`. Признак не различает утро и вечер. `minutes_to_target_1d` не учитывает выходные и вечернюю сессию.

**Как исправить.** Считать минуты от фактического начала торгового дня до `end` свечи, конец дня брать по расписанию сессий на эту дату (с 2025 года — утренняя сессия и торги выходного дня). `minutes_to_target_1d` = разница между `end` свечи и временем закрытия на `target_date_1d`.

### 8. Статусы таргетов

**Где:** `get_target_status`, ~стр. 121–137.

- Дата ROSB захардкожена как 14.11.2024, а последняя свеча — 11.11.2024; лучше брать дату последней сделки из данных.
- `MARKET_HALT` задан только диапазоном 25.02–24.03.2022; другие остановки (по отдельным бумагам) попадают в `NO_DATA`. Это нормально, но стоит описать.
- `SUSPENDED_OR_DELISTED` возможен только для 1w (для 1d ROSB уходит в `NO_DATA`) — привести к единообразию.

**Где:** `Parser/generate_pdf_datacard.py` (~стр. 285 и блок источников).

### 10. Новостной парсер

`news_parser_and_sentiment.py` собирает только текущие RSS-ленты (Ведомости, Коммерсантъ, ТАСС), в шапке файла при этом указаны Interfax, RBC, Banki.ru. Истории новостей он дать не может. Либо убрать из пайплайна, либо найти исторический источник и честно описать покрытие.
